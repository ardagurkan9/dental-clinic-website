# Dental Clinic Website

A modern, professional, and trustworthy website for a dentist or dental clinic. The project focuses on presenting the clinic clearly, showing services, and making contact or appointment actions easy for patients.

This is not a large backend application. The main focus is UI, page structure, content presentation, responsive design, and simple future additions such as contact or appointment forms.

## Purpose

- Present the clinic with a clean and credible digital identity.
- Help patients understand available dental services.
- Provide simple paths for contact, location, and appointment actions.
- Keep the experience fast, accessible, and mobile-friendly.

## Tech Stack

- Next.js
- React
- TypeScript
- Tailwind CSS

## Main Folders

- `app/` - Application routes, pages, and layout structure.
- `components/` - Reusable UI components.
- `data/` - Static website content such as services, navigation, clinic details, and placeholder text.
- `lib/` - Reusable helper functions and small utilities.
- `public/` - Public assets such as images, icons, and static files.

## Design Direction

The design should feel modern, calm, professional, and trustworthy. Prefer clean layouts, readable typography, strong spacing, accessible colors, and a polished mobile experience.

Do not copy real clinic websites exactly. Use original layouts and placeholder content unless approved real clinic content is provided.

## Development Rules

- Do not over-engineer.
- Keep components simple and focused.
- Work on one component or one feature at a time.
- Put static website content in `data/`.
- Put reusable helper functions in `lib/`.
- Put UI components in `components/`.
- Put public assets in `public/`.
- Do not add unused dependencies.
- Do not commit secrets, API keys, or `.env` files.

## AI Collaboration Rules

When using AI to work on this project:

- Keep the project frontend-focused and simple.
- Do not introduce large backend or enterprise-style architecture.
- Do not invent unused folders, services, or technologies.
- Make small, controlled changes.
- Reuse the existing folder structure.
- Use placeholder content unless approved real content is available.
- Keep the UI original and appropriate for a healthcare website.
